# M4.5 plan: Admin page

**Status: built (2026-09-30).** All steps are done and deployed; see "Build notes" at the
end. Waiting on Dan to set the admin password (`set-password` is interactive).

**Goal:** run and tune the logger from the browser: edit the Whisper prompt and substitutions
(with token counting, history and one-click revert), re-transcribe past clips to compare a
prompt change, test a prompt against the hand-labelled clips, reconnect the scanner or restart
the worker, and read recent logs. All of it sits behind a password, and talkgroup edits move
behind the same password.

## Exit criteria

- **Login:** `/admin` and all talkgroup edits require a password, set on the NUC with a CLI
  command. The browser stays logged in for 30 days. With no password set, admin features are
  disabled (fail closed) and the page says how to set one. Viewing the rest of the site stays
  open.
- **Prompt editor:** saving a new prompt takes effect **on the next clip without a
  restart**. A live token counter warns before the 223-token limit. History shows every
  version with a word diff, and any version can be made active again. Each transcript records
  which prompt version produced it.
- **Substitutions editor:** same versioning; changes apply to new transcripts immediately.
- **Re-transcribe:** choose a time range (plus optional talkgroups), see how many clips and
  roughly how long, confirm. Clips run at **low priority**, so live traffic is never delayed.
  A compare view then shows old vs new transcripts side by side.
- **Prompt test:** score the current (or a draft) prompt against the hand-labelled clips
  (WER, with the worst differences listed), run by the worker while idle. Results are kept per
  prompt version.
- **Commands:** "Reconnect scanner" and "Restart worker" work from the page, are acted on
  within about 5 s, and are recorded in the event log.
- **Logs:** the last few hundred lines from capture, worker and web, filterable by level.
- Tests: auth (login, cookie, expiry, fail-closed, rate limit), hot reload, versions and
  revert, re-transcribe priority and compare, commands, log tail, the prompt test. Browser
  checks for login and prompt editing.

| Topic | Decision | Why |

| Scope | All the extras: prompt + substitutions editors, re-transcribe with compare, logs, prompt A/B testing. | Dan |

## Design

### Auth

- `python -m scanner_transcriber set-password` (on the NUC) asks for a password and stores a
  **scrypt** hash (stdlib `hashlib.scrypt`, random salt) in a `settings` table. `--clear`
  removes it, which disables admin again.
- **Session:** a signed cookie (HMAC-SHA256 with a random secret generated on first run and
  kept in `settings`), 30-day expiry, `HttpOnly`, `SameSite=Strict`, and `Secure` when
  served over HTTPS (e.g. behind `tailscale serve`). Changing the password invalidates old
  sessions, because the secret rotates.
- `/login` (with `?next=`), `/logout`. Wrong passwords are **rate-limited**: exponential
  delay per client IP, reset on success.
- **Protected:** everything under `/admin`, and `PATCH/POST /api/channels…`. The
  `HX-Request` cross-site guard stays as a second layer.
- **No password set:** admin routes show "Admin is disabled until a password is set: run
  `… set-password` on the NUC". Talkgroup edit controls are hidden.

### Storage (migration 0006)

```sql
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TEXT NOT NULL);

CREATE TABLE prompt_versions (              -- also holds substitutions (kind = 'substitutions', JSON)
    id INTEGER PRIMARY KEY, kind TEXT NOT NULL CHECK (kind IN ('prompt', 'substitutions')),
    body TEXT NOT NULL, note TEXT, created_at TEXT NOT NULL, activated_at TEXT
);
CREATE TABLE active_versions (kind TEXT PRIMARY KEY, version_id INTEGER NOT NULL);

CREATE TABLE commands (                     -- polled by capture / worker supervisor
    id INTEGER PRIMARY KEY, target TEXT NOT NULL, action TEXT NOT NULL,
    created_at TEXT NOT NULL, taken_at TEXT, done_at TEXT, result TEXT
);

CREATE TABLE retranscribe_batches (
    id INTEGER PRIMARY KEY, created_at TEXT NOT NULL, since TEXT, until TEXT, tgids TEXT,
    prompt_version INTEGER, total INTEGER NOT NULL
);

CREATE TABLE prompt_evals (
    id INTEGER PRIMARY KEY, prompt_version INTEGER, draft_body TEXT, created_at TEXT NOT NULL,
    status TEXT NOT NULL, clips INTEGER, wer REAL, cer REAL, detail TEXT   -- JSON worst clips
);

ALTER TABLE transmissions ADD COLUMN prompt_version INTEGER;
ALTER TABLE transmissions ADD COLUMN subs_version INTEGER;
ALTER TABLE transmissions ADD COLUMN prev_transcript TEXT;        -- before a re-transcribe
ALTER TABLE transmissions ADD COLUMN prev_prompt_version INTEGER;
ALTER TABLE transmissions ADD COLUMN batch_id INTEGER;
```

### Hot reload

The worker checks `active_versions` before each clip (one indexed query). If the prompt or
substitutions version changed, it updates the Whisper generation config's `initial_prompt`
and its substitution map in place: no model reload, no restart. It writes `prompt_version` /
`subs_version` on every finished transcript. The detail page shows "Prompt version N" with a
link to that version.

### Admin page `/admin`

Sections (one page, anchored tabs on desktop, stacked on a phone):

1. **Prompt:**
   - a textarea with a **live token count** ("188 / 223"). It turns amber from 200 and red
     over 223, where text would be silently truncated.
   - Counting uses Whisper's own tokenizer (`tokenizers` package with the model's
     `tokenizer.json` from the local Hugging Face cache); htmx asks the server as you type.
   - A note field ("added 'I'm direct'").
   - **Save** makes it the active version immediately. The page says "Active since 14:02;
     used for 37 transcripts".
   - **History:** each version with date, note and a word diff against the previous one, plus
     **Make active** (revert) and **Test** (see 5).
   - A soft warning if the text contains 4+ consecutive common words that could trip the
     prompt-leak guard.
2. **Substitutions:** editable rows "heard as → replace with", add/remove, Save (new version,
   same history/revert).
3. **Re-transcribe:**
   - from/to pickers (quick: last hour / today), optional talkgroup chips, "include
     no-speech".
   - **Preview:** "212 clips, about 17 minutes at the current rate".
   - **Confirm** queues them at priority -1, saving each old transcript and prompt version to
     `prev_*`.
   - Each batch shows **progress** (done/total) and a **Compare** link: a list of old vs new
     with word-level highlights of what changed, filterable to "changed only".
   - Batch size is capped (default 2,000 clips) to avoid tying up the worker for hours.
4. **Scanner & worker:**
   - current state (from the status plumbing);
   - buttons **Reconnect scanner** (capture closes the RTSP session and reconnects, sending
     TEARDOWN as always) and **Restart worker** (the supervisor stops and starts it);
   - each shows "requested… done ✓" and lands in the event log.
5. **Prompt test:** runs the chosen prompt (the active one, any historical version, or the
   unsaved draft) over the hand-labelled clips in `data/sessions/*/refs.jsonl`. It shows
   WER/CER, a comparison with previous tests, and the worst clips (reference vs output).
   - The worker runs it **only while the live queue is empty**, so live latency is
     unaffected. It takes about 72 clips × 4.7 s, roughly 6 minutes.
   - Caveat shown on the page: those clips have been used to tune past prompts, so treat
     small WER changes as noise.
6. **Logs:** the tail of `data/logs/{capture,worker,web}.log` (rotating files, 1 MB × 3 each,
   set up by each process), level filter (all / warnings+), auto-refresh toggle. Under
   systemd (M5) the same files are still written, so the view keeps working.

### Commands

- `run` (capture + supervisor) polls `commands` every 5 s from its existing heartbeat task:
  - `capture/reconnect`: the live source ends its current session (TEARDOWN) and goes straight
    to reconnecting, without backoff.
  - `worker/restart`: the supervisor terminates the worker (it finishes the current clip) and
    starts it again.
- The worker polls between clips for `worker/prompt-test` (queued by the Prompt test section)
  and runs it when the live queue is empty.
- Each command records `taken_at` / `done_at` / `result` plus a `system_events` row. Commands
  older than 10 minutes that nobody took are marked expired (e.g. capture isn't running).

### Config changes

- `config.example.toml`: `[stt] prompt` and `[stt.substitutions]` replaced by a comment ("edit
  on the Admin page; a value here is only imported once into an empty database").
- `config.toml` (Dan's): the prompt is imported on first start. After that the startup
  warning suggests deleting it.

## Tests

- **Auth:** set/clear password (CLI), login success/failure, rate-limit delays, cookie
  tampering → rejected, expiry, password change → old cookies invalid, fail-closed with no
  password, `/admin` and channel edits → redirect/401 when logged out, read-only Talkgroups
  view.
- **Versions:** import from config once (not again on restart), save → active, revert, diff
  rendering, config-differs warning.
- **Hot reload:** a fake worker backend sees the new prompt on the next clip without a
  restart; `prompt_version` recorded.
- **Token counter:** the count matches the tokenizer; thresholds.
- **Re-transcribe:** preview count, cap, priority -1 behind live clips (claim order), `prev_*`
  saved, progress, compare view (changed only).
- **Commands:** reconnect makes the fake live source restart its session (TEARDOWN counted);
  restart worker; expiry; events.
- **Prompt test:** scoring over a synthetic labelled session with a fake backend; only runs
  while the queue is empty; results stored.
- **Logs:** tail with a level filter; rotation doesn't break it.
- **Browser (tests/ui):** log in, edit and save the prompt (counter updates while typing),
  revert, log out.

## Build notes (2026-09-30)

- **Auth** (`auth.py`): scrypt hash + session secret in `settings`; cookie `st_admin` =
  `<expiry>.<HMAC>`, 30 days, `HttpOnly`, `SameSite=Strict`, `Secure` behind HTTPS.
  `set-password` / `set-password --clear` rotate the secret. Login delay per client is 1, 2,
  4 … 60 s. `next=` only allows local paths. Talkgroup edit controls render only when logged
  in; the edit endpoints return 401 otherwise, or 403 while no password is set.
- **Prompt store** (`promptstore.py`): versions and active pointers. The config was imported
  once; `DEFAULT_PROMPT` is the 2026-09-30 prompt. **Dan's config.toml prompt was imported as
  version 1 and then removed from config.toml** (backup: `data/config.toml.bak-before-admin`).
  The worker's `apply_versions()` runs before every claim; prompt changes go to the backend's
  `prompt` attribute with no model reload. `prompt_version` / `subs_version` are recorded per
  transcript (degraded-mode transcripts get no prompt version).
- **Admin page** (`web/admin.py`, `_admin_*.html`):
  - prompt editor with an exact token count (the model's `tokenizer.json` from the local HF
    cache, via `tokenizers`), amber from 200, red over 223;
  - leak-guard hints: adjacent lower-case phrases making 4+ words;
  - history with word diffs; Make active; Test;
  - substitutions table.
- **Commands** (`commands.py`): `run` polls every 5 s (`handle_commands`). Reconnect raises
  `ReconnectRequested` inside the live source: TEARDOWN, then reconnect with no backoff. Worker
  restart goes through `WorkerSupervisor.restart()`. Untaken commands expire after 10 minutes.
- **Re-transcribe** (`retranscribe.py`): priority -1 (live 0), cap 2,000, oldest first,
  `prev_transcript` kept; `/admin/batches/{id}` compares old and new with word diffs.
- **Logs** (`logsetup.py`): `data/logs/{capture,worker,web}.log`, 1 MB × 3; viewer shows
  newest first, with a warnings filter and auto-refresh.
- **Prompt test** (`prompteval.py`): the worker runs one labelled clip per idle loop (live
  clips cut in) through the full guard/substitution path, then restores the active prompt.
  Word/char edit distance is stdlib (no jiwer in the worker). The "worst clips" list is kept.
- **Tests:** 217 pytest; browser checks `tests/ui/admin_check.py` (8 checks: login, counter,
  save, revert, logout) plus the earlier suites.
